# 実行時は Python の標準ライブラリだけで書く

## 背景と課題

hook は Claude Code のターンが終わるたびに起動される。利用者の環境で追加のセットアップなしに動き、起動が速いことが求められる。実装言語と依存の方針を決める必要がある。

## 判断基準

- clone 直後に追加インストールなしで動くこと
- macOS 標準の `python3`（3.9）で動くこと
- 起動が速いこと

## 検討した選択肢

1. Python 3.9 以上・標準ライブラリのみ
2. TypeScript（Node.js）
3. Go（ビルド済みバイナリを配る）

## 決定

選択肢 1 を採る。macOS には `python3` が標準で入っており、依存ゼロなら clone 直後に動く。

### 影響

- 良い: 利用者は `pip install` も `npm install` も不要
- 悪い: 3.9 で使えない構文（`match` 文、`X | Y` の型表記の実行時評価など）は使えない。`from __future__ import annotations` で型表記をそろえ、CI で 3.9 を回して担保する

### 確認方法

CI の matrix に Python 3.9 を含め、テストが通ること。`pyproject.toml` の実行時依存が空であること。

## 選択肢ごとの長所・短所

### 1. Python・標準ライブラリのみ

- 良い: 追加インストール不要。macOS・多くの Linux で動く
- 悪い: 3.9 互換の書き方に縛られる

### 2. TypeScript（Node.js）

- 良い: 型が強い
- 悪い: Node.js が入っていない環境では動かない。トランスパイルの手順が増える

### 3. Go

- 良い: 起動が最速で、単一バイナリ
- 悪い: OS・アーキテクチャごとのバイナリの配布と、利用者側での信頼の確認が要る
